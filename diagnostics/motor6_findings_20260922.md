# 6번 모터 정지 조사 — 2026-09-22

## 확인한 사실

- 사용자는 `오뒤412` 프레임을 1000ms 동안 적용하던 중 일부 관절이 풀리거나 멈췄으며, 해당 관절이 **6번**이라고 확인했다.
- GUI 구성상 6번은 오른쪽 팔꿈치(R_Elbow_Pitch), MX-28이다. 실제 모델 번호는 이번에 읽지 못했다.
- 마지막 성공 피드백에서 6번 목표/실제 각도는 34.98/31.38도였다. 약 3.60도 추종 오차만으로 과부하나 고장을 판정할 수 없다. 로그의 최대 오차 ID 17은 정지한 관절의 식별자가 아니다.
- 이후 SyncRead가 `There is no status packet!`으로 실패했다. 이 로그에는 응답 실패 ID가 없으므로 6번이 통신 실패 원인인지는 미확인이다.
- 20:10:42 및 20:11:23 USB 분리와 재등록, 20:11:24 descriptor error -71이 커널 로그에 있었다. **사용자가 오류 발생 후 직접 USB를 재연결했다고 확인했으므로 최초 증상의 원인 증거로 사용하지 않는다.**
- 프레임 이동 중에는 별도의 실시간 각도 갱신 타이머가 읽기를 생략한다. 두 읽기 경로가 동시에 포트를 사용했다는 근거는 없다.
- 프레임 목표 송신 성공은 모터의 수신/실제 도달 확인이 아니다. 피드백 실패가 송신 성공 반환값에 반영되지 않는 코드 경로를 확인했다.

## 조치와 한계

- `diagnose_mx_bus.py`를 MX-28(Protocol 2.0, 모델 30)에도 사용할 수 있도록 확장했다. 기존 MX-106(모델 321) 지원은 유지한다.
- MX-28의 주소 126은 추정 부하로 해석하고, 존재하지 않는 전류/전류 제한 항목은 출력하지 않는다. 토크·하드웨어 오류·전압·온도는 PING/READ로만 확인한다.
- GUI 최종각 완료 문구를 `송신 (모터 수신/도달 미확인)`으로 수정했다. 이번 조사에서 이동 속도나 모터 설정은 변경하지 않았다.
- 해석 테스트 3개, 파이썬 문법 검사, diff 공백 검사가 통과했다.
- USB 장치가 샌드박스에 노출되지 않아 외부 실행 권한을 요청했으나 사용자가 거절했다. **실제 모터 읽기는 수행하지 못했다.** 보호 정지·전원/배선·모터 자체 문제 중 원인을 확정할 수 없다.

6번과 비교용 7번을 읽을 때는 로봇을 지지하고 GUI 등 다른 시리얼 프로그램을 종료한 상태여야 한다. 도구는 포트를 다른 프로세스가 사용 중이면 중단한다. 재부팅 전 상태가 가장 유용하며, 정상 응답으로 회복된 뒤의 결과로 이전 고장을 배제할 수 없다.
